 1. ERRORES ENCONTRADOS
-------------------------------------------------------------------------------

1.1 [ALTO] Información financiera y de empleados visible SIN iniciar sesión
    App: Modulo-contable
    Archivos: routes/contabilidad.py, routes/nomina.py
    Prueba realizada: sin iniciar sesión, estas direcciones respondieron
    200 (OK) y entregaron datos:
        /api/contabilidad/consolidado
        /api/contabilidad/balance-general
        /api/contabilidad/estado-resultados
        /api/contabilidad/exportar-reporte?formato=excel  (descarga el Excel)
        /api/nomina/empleados   (nombres, documentos y salarios)
        /api/nomina/resumen
    En cambio, /api/inventario/productos sí responde 401 (pide sesión), que
    es lo correcto.
    Causa: a esas rutas les falta el decorador @login_requerido o
    @requerir_roles(...).
    Recomendación: proteger todas las rutas /api/ con el decorador que
    corresponda al rol, como ya se hace en inventario.

1.2 [ALTO] Clave secreta de sesión escrita en el código
    App: Modulo-contable   Archivo: app.py
        app.secret_key = 'exodus-contable-dev-secret'
    Con esa clave, cualquiera que vea el repositorio puede fabricar una
    cookie de sesión y entrar con rol "Administrador" sin contraseña.
    Recomendación: generarla al azar y leerla de un archivo fuera del repo o
    de una variable de entorno, como ya hace Exodus-login
    (instance/secret_key).

1.3 [ALTO] "Recordarme" guarda la contraseña en la cookie
    App: Exodus-login   Archivo: app.py (función login)
    Al marcar "Recordarme", se guarda {"usuario": ..., "clave": ...} en la
    cookie "exodus_usuario". La cookie está FIRMADA (no se puede modificar)
    pero NO CIFRADA: su contenido se puede decodificar y leer la contraseña.
    El propio comentario del código dice "no en texto plano", y no se cumple.
    Recomendación: guardar solo el nombre de usuario, como ya hace
    Modulo-contable en routes/auth.py.

1.4 [MEDIO] Error 500 al crear o editar un rol con permisos  (YA CORREGIDO)
    App: Exodus-login   Archivos: modulos/roles.py, db.py
    En Configuración > Roles, al marcar permisos y guardar, la app fallaba
    con error 500. Se llamaba a db.executemany(...), pero la clase Conexion
    de db.py no tenía ese método.
    Además, el rol se guardaba (commit) ANTES de asignar los permisos, así
    que quedaba creado a medias, sin permisos.
    Corrección aplicada:
      - Se agregó el método executemany a la clase Conexion (db.py).
      - Se quitó el commit intermedio en roles.py: rol y permisos se
        guardan juntos.
    Verificado: crear, editar y eliminar roles con permisos funciona.

1.5 [MEDIO] El script SQL no coincide con lo que usa el código
    App: Modulo-contable   Archivo: sistema_contable.sql
    - La tabla "usuarios" del .sql no tiene las columnas usuario, clave_hash
      ni activo. La app las agrega al arrancar con ALTER TABLE
      (database/init_db.py).
    - Las tablas empleados, deducciones, aportes, nomina, novedades,
      productos y movimientos_inventario no están en el .sql; las crea el
      código.
    Si alguien importa solo el .sql y la app no logra conectarse al inicio,
    el login falla.
    Recomendación: exportar de nuevo el .sql con la estructura completa y
    actualizada.

1.6 [MEDIO] Modo debug activado de forma fija
    App: Modulo-contable   Archivo: app.py
        app.run(debug=True, port=5000)
    El depurador de Flask permite ejecutar código desde el navegador si se
    produce un error. No debe quedar activo fuera del desarrollo.
    Recomendación: activarlo con una variable de entorno, como Exodus-login
    (EXODUS_DEBUG=1).


-------------------------------------------------------------------------------
 2. RECOMENDACIONES DE SEGURIDAD
-------------------------------------------------------------------------------

2.1 Credenciales de base de datos fijas en el código
    Modulo-contable/database/connection.py usa root sin contraseña, sin
    puerto configurable. modulo-nomina/config/db.php también usa root.
    Recomendación: crear un usuario de MySQL propio para la app (no root) y
    leer host, puerto, usuario y clave de variables de entorno, como hace
    Exodus-login/db.py.

2.2 Contraseñas de demostración débiles y escritas en el código
    database/init_db.py (CREDENCIALES_DEMO) y Exodus-login/db.py crean
    usuarios como admin/admin123. Sirven para pruebas, pero en una entrega
    real cualquiera podría entrar con ellas.
    Recomendación: crearlas solo en modo desarrollo u obligar a cambiarlas
    en el primer ingreso.

2.3 El bloqueo por intentos fallidos se guarda en memoria
    Ambas apps bloquean 5 minutos tras 5 intentos fallidos. El registro está
    en un diccionario en memoria (_intentos): se borra al reiniciar la app y
    no funciona si hay varios procesos.
    Recomendación: guardarlo en la base de datos si se necesita persistencia.

2.4 Las rutas /api/ no tienen protección CSRF
    Modulo-contable exime las rutas /api/ de la verificación CSRF, y nómina
    acepta datos de formulario además de JSON (request.form). La cookie
    SameSite=Lax reduce el riesgo, pero no reemplaza la verificación.
    Recomendación: exigir JSON (Content-Type application/json) en las APIs
    o validar un token CSRF en el encabezado.


-------------------------------------------------------------------------------
 3. RECOMENDACIONES DE ESTRUCTURA Y ORGANIZACIÓN
-------------------------------------------------------------------------------

3.1 Dos sistemas de usuarios separados
    Modulo-contable usa la base "sistema_contable" y Exodus-login usa
    "exodus_contable". Cada una tiene su propia tabla de usuarios y roles,
    con nombres distintos ("Administrador" vs "administrador"). Un usuario
    creado en una app no existe en la otra.
    Recomendación: definir una sola app de login o una sola base de usuarios
    compartida.

3.2 Módulo de nómina duplicado
    modulo-nomina (PHP + base exodus_nomina) ya fue portado a Python dentro
    de Modulo-contable. Mantener las dos versiones confunde y obliga a
    corregir todo dos veces.
    Recomendación: dejar una sola versión, o marcar la de PHP como archivada.

3.3 Archivos duplicados en la carpeta de plantillas  (YA ELIMINADOS)
    Exodus-login/templates/modulos/*.py eran copias de Exodus-login/modulos/
    con el mismo error del punto 1.4. Ningún archivo los usaba: Flask usa
    templates/ solo para HTML. Se eliminaron y se pueden recuperar desde git.

3.4 Dos copias del repositorio (Exodus y Exodus-1)
    La carpeta "Exodus" tiene una versión más antigua del mismo proyecto.
    Recomendación: trabajar solo en una y mantenerla actualizada con
    git pull.

3.5 Falta requirements.txt en Exodus-login
    Solo Modulo-contable lo tiene. Exodus-login necesita Flask y PyMySQL.
    Recomendación: agregar Exodus-login/requirements.txt.

3.6 Modulo-contable/config.py está vacío
    Recomendación: centralizar ahí la configuración (clave secreta, datos de
    la base, modo debug) o eliminar el archivo.

3.7 Faltan instrucciones de instalación
    El archivo readm.md (nombre mal escrito; debería ser README.md) contiene
    el documento de requisitos, pero no explica cómo instalar ni ejecutar.
    Recomendación: agregar los pasos: instalar dependencias, crear e importar
    la base, configurar la conexión, ejecutar y usuarios de prueba.


-------------------------------------------------------------------------------
 4. CALIDAD DE CÓDIGO (avisos de Pylint - no impiden el funcionamiento)
-------------------------------------------------------------------------------

4.1 Se usa "except Exception" muy general (app.py, models/inventario.py,
    services/consolidacion_service.py, routes/inventario_modulo.py).
    Puede ocultar errores reales. Mejor capturar excepciones concretas.

4.2 Se relanzan errores sin "from" (models/inventario_stock.py,
    routes/inventario_modulo.py, services/balance_service.py,
    services/gasto_service.py). Usar "raise ... from exc" conserva el
    error original y facilita depurar.

4.3 Se usa "id" como nombre de variable (routes/configuracion.py,
    modulos/*.py). Tapa la función id() de Python; mejor "id_rol",
    "id_usuario", etc.

4.4 open() sin encoding (Exodus-login/app.py, lectura de secret_key).
    Agregar encoding="utf-8".

4.5 Estilo: líneas de más de 100 caracteres, espacios al final de línea,
    funciones sin docstring e imports de flask sin agrupar
    (routes/contabilidad.py).
